#
# A ratchet, exactly like test-roms-pl's floor.txt: set from the measured sweep
# rounded DOWN to the nearest whole percent, so a propagation regression shows
# up as a drop rather than as a subtly worse picture nobody notices. Re-pin
# deliberately, in its own commit, when propagation improves.
#
# A workload with no line here is a WARNING, not an error — unlike a missing
# trace golden, which stays fatal. A new rip should not fail the gate before
# anyone has measured it.
#

# --- A second ratchet lives below: per-workload CEILINGS on `clamped`. ---
#
# `clamped` counts a resolved vertex whose pre-clamp f32->16.16 conversion
# disagreed with the pixel `primitive.zig`'s `toFixed` actually clamped it
# into (see CLAUDE.md's PGXP rules and the `ps1-pgxp` skill). The clamp keeps
# the vertex correct on screen, so this is not a hit rate and is not read the
# same way: it is a RATCHET on how often the clamp has to intervene, exactly
# like the percentages above are a ratchet on how much resolves. A workload
# with no `clamped` line here WARNs instead of failing, same as one with no
# hit-rate floor above.
#
# Syntax: `clamped <workload key> <count>`, parsed by `parseClampCeilings`
# (and skipped by the hit-rate parser above, `parseFloors`, on the `clamped `
# prefix) — both ratchets share this one file on purpose, so a workload's two
# numbers are read together.
#
# THESE NUMBERS EXPLODED ON 2026-09-12 AND ARE THE TOP OPEN QUESTION OF THE
# PHASE. Nine of ten workloads clamped ZERO vertices before CPU mode shipped
# on; croc now clamps 81,466 of its 199,788 resolved vertices (41%) and spyro
# 52,591. Pinned at the measured counts because that is this file's rule and
# because a ratchet set below what HEAD measures gates nothing — but pinned
# with the caveat written down rather than absorbed silently.
#
# What is NOT yet known is the composition of that count, and it matters:
#   - A shadow whose float landed a hair BELOW its own integer (p.x = 99.9999
#     against wire x = 100) clamps by 1/65536 px and is completely benign.
#   - A CPU-mode shadow that genuinely drifted a pixel or more from the vertex
#     it claims to describe also clamps, is NOT benign, and is exactly what the
#     `pgxp_tolerance` setting exists to refuse.
# `clamped` cannot currently tell the two apart. Splitting it — a second
# counter for a disagreement above, say, one whole pixel — is the cheapest next
# measurement anyone can take here, and it should come before any conclusion
# about whether CPU mode's picture is as good as its hit rate.
#
# Measured 2026-09-12, the same run as the hit rates above.
